# CsharpWorkshop 備課

將已確認的課程規格做成可閱讀、可練習、可執行驗證的教材。本 skill 僅適用本專案。

## 先確定這次要做什麼

依學生當次要求選擇範圍；既有授權仍有效，無須為例行製作教材再次確認。

| 要求 | 完成界線 |
|---|---|
| 準備課程／調整教材 | 完成教材與製作檢查，記錄已驗證及待辦項目；Ticket 保持進行中。 |
| 最後驗收／結案 | 逐項核對 Ticket；全數通過後標為 resolved，補上結果與地圖指標。 |
| 調整歸檔範圍 | 更新追蹤文件，明列要保留的知識、素材及待整理工作。 |
| 正式歸檔 | 依歸檔 Ticket 與 README 執行搬移、索引更新及清理。 |

完成當次範圍即停止；下一單元、commit、push 依學生指示進行。教材準備完成與學生說「沒有問題」均不自行視為結案要求。

## 取得上下文與教學參考

1. 讀取專案根目錄的 `AGENTS.md`、README 的分類／暫存規則，以及 `docs/agents/issue-tracker.md`。讀取指定 Ticket、所屬 spec／map 與阻擋 Ticket；開始未結案單元的備課前，先依 tracker 設為 claimed。阻擋未解除時，說明相依關係，先做不依賴阻擋項目的準備。
2. 製作或修訂教學內容時，讀取目前的 [teach](../teach/SKILL.md) 與 [相容性基準](references/teach-compatibility.md)。將 teach 當作教學設計參考，不隱含啟動它整套個人學習工作流程。純驗收既有教材時只需檢查原有設計與本次驗收範圍。
3. 目的、先備知識與難度優先取自已確認的 spec／Ticket／教材，不因缺少 MISSION.md 就重做訪談；確有影響教材內容的缺口才詢問學生。

上下文檔案路徑相對於專案根目錄；上面的 teach 與相容性連結相對於本 skill。建立教材前先確認教學工作區，之後 teach 的 `lessons/`、`reference/`、`assets/` 等路徑一律相對於該工作區，不依 shell 當前位置判斷。

## 準備一個單元

- 沿用該 feature 的 `.scratch/YYYYMMDD-<feature-slug>/`，單元教材放在 `course/<NN>-<slug>/`；已有指定位置時沿用。先讀取既有共用元件與專案位置，復用樣式、互動元件與 Console 入口；保留已確認的跨單元共用專案，不為每單元或參考解另建專案。
- 依 teach 設計 HTML 短課程、即時回饋及獨立速查頁；單元採「簡短說明 → 範例 → 預測輸出 → 執行觀察 → 修改練習」。題目後另設解答，HTML 解答預設收合；解釋題附判準，預測題附實測輸出，修改題附可執行參考解。
- 每個單元只帶入解答主要問題所需概念，延伸話題分為補充閱讀。已有 Markdown 主線與來源素材時保留，從它連到 HTML 入口；共用資料與教材位置可不同，但連結與命令須明確。
- 技術敘述查證 Microsoft Learn、.NET 官方文件或原始碼；記錄來源、適用版本及驗證日期。區分公開 API 行為與指定 .NET 版本的實作細節，來源用途記入 RESOURCES.md。
- 新專案先檢查可用 SDK 及專案慣例，記錄目標框架，保留其他既有專案。C# Console 使用明確的 `Program` 類別與 `static void Main(string[] args)`，符合本專案學生已表達的閱讀偏好。
- 需要 MISSION.md 時，依 teach 的格式從既有 spec 摘錄教學目的；NOTES.md 只記教材設計、教學偏好與工作備註。這是知識庫，不建立 learning-records、個人能力檔案或自動儲存學生作答。
- 編譯工具的額外初始化／快取使用系統暫存區；專案正常的 bin／obj 留在專案內，不在 feature 根目錄建立臨時工具目錄。

## 製作檢查與最後驗收

兩者使用相同證據；是否結案由當次要求決定。保留仍適用的既有驗證，只重跑本次變更或未解問題影響的項目。

1. 建置共用專案，實際執行本單元示範與參考解，核對教材、專案說明與執行輸出；檢查 repo 根目錄及專案目錄所列命令，包含預設入口。發現不一致時修正後重驗相關項目。
2. 對照說明、範例、題目、解答與判準。HTML 若採較短程式，說明與完整示範的輸出差異；互動答案以實際可執行行為為依據。新增或修改互動邏輯時驗證正誤答案、未作答及支援的輸入方式。
3. 檢查本機連結、錨點、CSS／JS 引用；HTML 變更時盡可能在瀏覽器檢查顯示與互動。紀錄清楚區分程式邏輯檢查、瀏覽器互動測試與視覺檢查，未執行的檢查不能寫成通過。
4. 依 Ticket 的當前範圍核對目錄與索引。暫存教材不加入正式索引；若單元條件混入整套正式歸檔，將該工作保留於獨立歸檔 Ticket，並同步修正 spec／map 中的目前狀態，不能刪掉義務或只勾選略過。
5. 備課只記錄結果並保持 claimed。學生要求最後驗收且條件全數通過時，勾選條件、設為 resolved，在 `## Answer` 記錄日期、證據與限制，於 map 補連結；修正教材上「本單元尚未結案」等過時敘述。仍有未通過項目則明列原因與待辦，維持進行中。

若 Ticket 是 ready-for-agent 等 triage 狀態，依 repo tracker 的 claimed／resolved 約定表達實際處理狀態；不將教材狀態解讀為學生掌握程度。

## 課堂延伸與正式歸檔

學生希望保留的延伸知識，即使原素材只是隨手筆記，也納入歸檔追蹤：連到原始素材，寫清楚要整理的主題、查證與查詢入口。原始筆記維持原文；正式知識內容以概念與範例整理。

單元可在暫存區內完成並結案；整套歸檔 Ticket 等必要單元完成後再執行，不反過來阻擋單元結案。正式位置、索引與暫存清理依 README 當前規則辦理。清理前核對原始素材的保留與已整理內容，確保所需內容或歷史版本可取回，並釐清尚未決定去向的個人筆記。

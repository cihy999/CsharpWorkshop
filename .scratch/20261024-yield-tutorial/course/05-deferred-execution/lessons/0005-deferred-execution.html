01 / 呼叫方法，主體一行都還沒跑

上一課看過：每次 MoveNext()，產生端從上次暫停處跑到下一個 yield return。那第一次 MoveNext() 之前呢？本課的產生端是這個迭代器方法，主體每一段都印出標記：

private static IEnumerable<int> Steps()
{
    Console.WriteLine("[產生端] 進入方法主體");
    Console.WriteLine("[產生端] 產出 1");
    yield return 1;

    Console.WriteLine("[產生端] 從產出 1 之後繼續，產出 2");
    yield return 2;

    Console.WriteLine("[產生端] 從產出 2 之後繼續，產出 3");
    yield return 3;

    Console.WriteLine("[產生端] 從產出 3 之後繼續，走到方法結尾");
}

消費端呼叫 Steps()、再呼叫 GetEnumerator()，但一次都不呼叫 MoveNext()。實測輸出：

[消費端] 呼叫 Steps() 之前
[消費端] 呼叫 Steps() 之後
[消費端] GetEnumerator() 之前
[消費端] GetEnumerator() 之後
[消費端] 不再要求元素

沒有任何一行 [產生端]。呼叫迭代器方法只拿到一個「之後可以列舉」的物件；取得列舉器也還沒執行主體。官方：呼叫迭代器不會立即執行它 · C# 規格：Enumerable objects

呼叫 Steps() 並取得列舉器後，產生端印出了？

02 / 要幾個，就跑到第幾個

三種情境用同一個消費端方法，只差在要求幾次：情境 1 是 0 次，情境 2 是 2 次，情境 3 是 4 次（第 4 次回傳 False）。

private static void RequestElements(IEnumerable<int> sequence, int requestCount)
{
    Console.WriteLine("[消費端] GetEnumerator() 之前");
    using (IEnumerator<int> enumerator = sequence.GetEnumerator())
    {
        Console.WriteLine("[消費端] GetEnumerator() 之後");

        for (int i = 1; i <= requestCount; i++)
        {
            Console.WriteLine("[消費端] 第 " + i + " 次 MoveNext() 之前");
            bool moved = enumerator.MoveNext();
            if (moved)
            {
                Console.WriteLine("[消費端] 第 " + i + " 次 MoveNext() 之後：True，Current = " + enumerator.Current);
            }
            else
            {
                Console.WriteLine("[消費端] 第 " + i + " 次 MoveNext() 之後：False，序列結束");
            }
        }

        Console.WriteLine("[消費端] 不再要求元素");
    }
}
消費端做的事產生端執行的部分
呼叫 Steps()無
GetEnumerator()無
第 1 次 MoveNext()從方法開頭到 yield return 1
第 2 次 MoveNext()從 yield return 1 之後到 yield return 2
不再要求無；yield return 2 之後的程式不會執行

這張表就是情境 2（只要求 2 個）。產生端只做被要求的那部分：消費端停下來，主體就停在 yield return 2，「從產出 2 之後繼續」永遠不會印出。C# 規格：第一次 MoveNext 從開頭執行

情境 2 只要求 2 個元素，「從產出 2 之後繼續」會印出嗎？

情境 2 離開 using 時會呼叫列舉器的 Dispose()。Steps() 沒有 finally，所以這時沒有輸出；提前停止與清理留到單元 6。

03 / 延遲來自 yield，不是回傳型別

單元 4 的 return 版也回傳 IEnumerable<int>。完整示範最後一段只呼叫它、不列舉：

private static IEnumerable<int> StepsWithList()
{
    Console.WriteLine("[產生端] 進入 StepsWithList() 主體，建立 List");
    List<int> numbers = new List<int> { 1, 2, 3 };
    Console.WriteLine("[產生端] 用 return 交出 List");
    return numbers;
}
[消費端] 呼叫 StepsWithList() 之前
[產生端] 進入 StepsWithList() 主體，建立 List
[產生端] 用 return 交出 List
[消費端] 呼叫 StepsWithList() 之後，尚未列舉

回傳型別一樣，主體卻在呼叫時就跑完了。所以本課的結論只針對主體含 yield return 的迭代器方法；只看到方法回傳 IEnumerable<T>，判斷不出它何時執行。官方：只看 IEnumerable 無法推斷執行時機

StepsWithList() 也回傳 IEnumerable<int>，呼叫時主體會？

LINQ 的 Where、Select 等方法也有延遲行為，但各方法細節不同，不在本課範圍；這裡不把結論推廣到所有 IEnumerable 方法。

04 / 排序事件標記

以下程式會印出部分標記。候選標記有 A、B、C1、D2、E、P、Q、R，其中有一個不會出現。先排出實際印出的順序，再核對。

static IEnumerable<int> Two()
{
    Console.WriteLine("P");
    yield return 1;
    Console.WriteLine("Q");
    yield return 2;
    Console.WriteLine("R");
}

IEnumerable<int> sequence = Two();
Console.WriteLine("A");
using (IEnumerator<int> e = sequence.GetEnumerator())
{
    Console.WriteLine("B");
    if (e.MoveNext())
    {
        Console.WriteLine("C" + e.Current);
    }
    if (e.MoveNext())
    {
        Console.WriteLine("D" + e.Current);
    }
}
Console.WriteLine("E");

排序題解答與原因
A
B
P
C1
Q
D2
E

呼叫 Two() 時主體沒有執行，所以先印 A；GetEnumerator() 也不執行主體，接著印 B。第 1 次 MoveNext() 從開頭執行，印出 P 後停在 yield return 1，消費端印 C1；第 2 次從下一行繼續，印出 Q 後停在 yield return 2，消費端印 D2。之後沒有再要求，R 那一行不會執行，離開 using 後印 E。這段程式於 2026-11-21 以 .NET 10 在暫存專案實測。

05 / 移動一行，再預測

目標：只移動主體裡的一行輸出，重新預測三種情境。

  1. 在 DeferredExecution.cs 新增 StepsMovedExercise()，先複製 Steps()。
  2. 把第一行 Console.WriteLine("[產生端] 進入方法主體"); 移到 yield return 2; 之後、「從產出 2 之後繼續」那行之前。
  3. 這行已不在開頭，把文字改成 "[產生端] 移動過來的標記"。
  4. 仿照 Run() 的三個情境改呼叫新方法。要執行時，可暫時在 Program.cs 加一個選項（例如 05-exercise），練習後再還原。

先預測：三種情境中，這行各會不會出現？若出現，在第幾次 MoveNext() 時？

修改題參考解
private static IEnumerable<int> StepsMoved()
{
    Console.WriteLine("[產生端] 產出 1");
    yield return 1;

    Console.WriteLine("[產生端] 從產出 1 之後繼續，產出 2");
    yield return 2;

    Console.WriteLine("[產生端] 移動過來的標記");
    Console.WriteLine("[產生端] 從產出 2 之後繼續，產出 3");
    yield return 3;

    Console.WriteLine("[產生端] 從產出 3 之後繼續，走到方法結尾");
}
情境「移動過來的標記」
1：不要求元素不出現
2：只要求 2 個不出現
3：要求到結束第 3 次 MoveNext() 時，緊接在「從產出 2 之後繼續」那行之前

情境 3 的實測片段：

[消費端] 第 2 次 MoveNext() 之後：True，Current = 2
[消費端] 第 3 次 MoveNext() 之前
[產生端] 移動過來的標記
[產生端] 從產出 2 之後繼續，產出 3
[消費端] 第 3 次 MoveNext() 之後：True，Current = 3

原本開頭那行在第 1 次 MoveNext() 時印出；移到 yield return 2 之後，就要等第 3 次要求才會執行，只要求 2 個時永遠不印。一行程式何時執行，取決於它在哪兩個 yield return 之間，以及消費端要求了幾次。專案另附獨立解答：dotnet run -- 05-answer。

解釋題判準

能說出三點即可：呼叫迭代器方法與 GetEnumerator() 都不執行主體，第 1 次 MoveNext() 才從開頭執行到第一個 yield return。之後每次要求只再往下跑一段；情境 2 只要求兩次，主體停在 yield return 2，後面的程式沒有執行。延遲執行是迭代器方法（主體含 yield return）的行為，不是 IEnumerable<int> 這個回傳型別造成的：StepsWithList() 回傳型別相同，呼叫時就跑完主體。

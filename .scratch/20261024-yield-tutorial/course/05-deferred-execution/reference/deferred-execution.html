迭代器延遲執行速查

.NET 10 · 查證日期 2026-11-21

回到課程yield 暫停與繼續速查列舉器協定速查

時間線

消費端做的事迭代器方法主體
呼叫迭代器方法不執行；只回傳可列舉的物件
GetEnumerator()不執行；只回傳列舉器
第 1 次 MoveNext()從開頭執行到第一個 yield return（或結尾）
之後每次 MoveNext()從上次暫停處的下一行執行到下一個 yield return（或結尾）
不再要求暫停處之後的程式不執行

三種消費情境（Steps() 有三個 yield return）

情境MoveNext() 次數主體執行到哪裡
只取得列舉器0一行都沒執行
部分列舉2停在 yield return 2
完整列舉4（第 4 次為 False）走到方法結尾

判斷一行程式何時執行

  1. 它所在的方法主體有沒有 yield return？沒有就是一般方法，呼叫時執行。
  2. 有的話，數它前面有幾個 yield return：前面有 k 個，就在第 k + 1 次 MoveNext() 時執行。
  3. 消費端要求不到那一次，這行就不執行。

邊界

不要這樣推論原因
「回傳 IEnumerable<T>，所以延遲執行」一般方法用 return 交出 List，回傳型別相同，呼叫時就執行完主體。
「所有 IEnumerable 方法、所有 LINQ 運算都一樣」本課只驗證同步 yield 迭代器方法；其他方法的行為要看各自文件。
「看誰先跑完、等一下再看」順序由輸出先後決定；示範沒有計時或等待。

用語

名稱本課含義
延遲執行呼叫迭代器方法時不執行主體，開始列舉（第一次 MoveNext()）才執行。
部分列舉消費端只要求部分元素就不再要求。
完整列舉要求到 MoveNext() 回傳 False。
產生端／消費端沿用單元 4：迭代器方法／要求元素的程式。

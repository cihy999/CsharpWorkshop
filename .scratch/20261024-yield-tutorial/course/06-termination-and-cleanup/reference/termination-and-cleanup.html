三種停止路徑對照

路徑誰決定停下剩餘一般程式已進入 try 的 finally
走到方法結尾產生端（自然耗盡）在結尾前已依序執行完離開 try 時執行一次
yield break產生端（提早結束序列）不執行（含 finally 之後的程式）在 MoveNext() 回傳 False 前執行一次
foreach 內 break消費端（不再要求元素）不執行foreach 收尾呼叫 Dispose() 時執行一次

三種 break 不要混淆

寫法與位置作用對象
迭代器內的 yield break;直接結束整個迭代器序列，讓 MoveNext() 回傳 False
迭代器內 for／while 的一般 break;只跳出該內部迴圈，方法繼續往下執行迴圈後的程式
消費端 foreach 內的一般 break;跳出消費端的 foreach，並在離開時對列舉器呼叫 Dispose()

Dispose() 與 finally 規則

呼叫 Dispose() 時列舉器的位置結果
尚未開始（從未呼叫過 MoveNext()）主體未執行、未進入 try，不執行主體內的 finally
暫停在某個 try 區塊內的 yield return執行包圍該暫停點的 finally，不執行剩餘一般程式
已經結束（已走到底或已 yield break）無額外動作，finally 不會重複執行

誰負責呼叫 Dispose()？

  • 使用 foreach：語意上自帶外圍 try／finally，正常走完、break、return 或擲出例外離開時，都會自動對列舉器呼叫 Dispose()。
  • 手動呼叫 GetEnumerator()：沒有 foreach 代勞，必須由呼叫者以 using（或在自己的 finally 中呼叫 Dispose()）負責收尾，否則提前停止時產生端的 finally 不會執行。

常見誤解

不要這樣推論原因
「yield return 暫停回傳時會先跑一次 finally」暫停在 try 內時資源仍須保留給後續迭代，當下不執行 finally。
「消費端 break 會把迭代器剩下的程式跑完」沒有新的 MoveNext()；Dispose() 只執行已進入 try 的 finally。
「只要方法裡寫了 finally，不列舉也會執行」從未 MoveNext() 就沒進入 try，沒有開啟區段就不執行該 finally。

用語

名稱本課含義
yield break產生端在迭代器內明確宣告「序列到此結束」的陳述式。
提前停止消費端在序列耗盡前停止要求後續元素（例如 foreach 中途 break）。
已進入的清理區段控制流已經進入、但尚未離開的 try 區塊所對應的 finally（或 using）。

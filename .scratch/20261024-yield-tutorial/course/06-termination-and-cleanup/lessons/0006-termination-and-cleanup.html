01 / 產生端怎麼結束：走到結尾 vs yield break

我們直接讀一個完整的迭代器方法（try／finally 語法由教材提供，不必自己默寫）。把需要配對收尾的工作放在 try，收尾動作放在 finally：

private static IEnumerable<int> ReadNumbers(int stopAt)
{
    try
    {
        Console.WriteLine("[產生端] 開啟資源（進入 try）");

        for (int n = 1; n <= 3; n++)
        {
            if (n == stopAt)
            {
                Console.WriteLine("[產生端] 遇到 n = " + n + "，執行 yield break");
                yield break;
            }

            Console.WriteLine("[產生端] 產出 " + n);
            yield return n;
            Console.WriteLine("[產生端] 從產出 " + n + " 之後繼續");
        }

        Console.WriteLine("[產生端] 迴圈正常走完");
    }
    finally
    {
        Console.WriteLine("[產生端] finally：釋放資源");
    }

    Console.WriteLine("[產生端] 走到方法結尾");
}

先注意一個關鍵細節：在 try 裡面遇到 yield return n; 時，方法只是暫停，finally 還不會執行——否則剛拿到第 1 個值，資源就被關掉了。C# 規格：yield return 暫停時不執行 finally

由產生端自己結束序列有兩種方式：

產生端路徑發生什麼事會不會印「走到方法結尾」？
自然走完（stopAt = 0）1、2、3 都產出後，第 4 次 MoveNext() 離開 try、執行 finally，再走到方法結尾回傳 False會
提早結束（stopAt = 2）產出 1 後，第 2 次 MoveNext() 遇到 yield break，先執行已進入 try 的 finally，直接回傳 False不會

別把產生端裡的 yield break 和一般 break 混為一談：如果在上面的 for 迴圈寫一般 break，只是跳出 for 迴圈，還會繼續印出「迴圈正常走完」與「走到方法結尾」；yield break 則是直接結束整個迭代器序列。官方：以 yield break 結束序列 · 官方：一般 break

產生端在 try 裡執行 yield break 時，接著會發生什麼？

語法限制：yield return 與 yield break 可以寫在「只有 finally、沒有 catch」的 try 區塊中；finally 區塊本身裡面不能寫 yield return 或 yield break。官方：yield 的限制與 using

02 / 消費端怎麼停下：foreach 裡的 break

換成消費端決定只拿 1 個就不讀了（stopAt = 0，產生端原本準備提供 1、2、3）：

foreach (int number in ReadNumbers(0))
{
    Console.WriteLine("[消費端] 取得 " + number);
    if (number == 1)
    {
        Console.WriteLine("[消費端] 執行 break，離開 foreach");
        break;
    }
}
Console.WriteLine("[消費端] foreach 結束");

實測輸出：

[產生端] 開啟資源（進入 try）
[產生端] 產出 1
[消費端] 取得 1
[消費端] 執行 break，離開 foreach
[產生端] finally：釋放資源
[消費端] foreach 結束

對照這六行，看清楚兩件事：

  • 剩餘的一般程式不會執行：沒有人再呼叫第 2 次 MoveNext()，所以「從產出 1 之後繼續」「產出 2」「迴圈正常走完」「走到方法結尾」全部不出現。
  • 已進入的 finally 仍會執行：當時列舉器正暫停在 try 區塊裡的 yield return 1，離開 foreach 時會執行這個 try 對應的 finally。

03 / 誰觸發了 finally？沒開始列舉又會怎樣？

為什麼消費端只寫了 break，產生端的 finally 卻知道要執行？回到單元 3：foreach 在語意上會把迴圈包進 try／finally，無論正常走完、中途 break 或發生例外，離開 foreach 時都會呼叫列舉器的 Dispose()。C# 規格：foreach 的收尾

如果不用 foreach，改用手動呼叫 GetEnumerator()，就沒有 foreach 幫忙收尾，必須由呼叫者自己用 using（或手動呼叫 Dispose()）負責。完整示範的兩個對照把這件事攤開來看：

// 對照 1：取得 1 個元素後離開 using
using (IEnumerator<int> enumerator = ReadNumbers(0).GetEnumerator())
{
    if (enumerator.MoveNext())
    {
        Console.WriteLine("[消費端] 手動取得 " + enumerator.Current);
    }
    Console.WriteLine("[消費端] 準備離開 using");
}
Console.WriteLine("[消費端] 已離開 using");

// 對照 2：取得列舉器，但從未呼叫 MoveNext 就離開 using
using (IEnumerator<int> enumerator = ReadNumbers(0).GetEnumerator())
{
    Console.WriteLine("[消費端] 已取得列舉器，但不呼叫 MoveNext");
}
Console.WriteLine("[消費端] 已離開 using");
離開 using（呼叫 Dispose()）時的狀態Dispose() 做的事
尚未開始（沒呼叫過 MoveNext()）主體還沒執行、沒進入 try，不執行主體的 finally
暫停在 try 內的 yield return執行該 try 對應的 finally，不跑剩餘一般程式
已經結束（走到底或已 yield break）先前結束時已清理過，不再重複執行 finally

對照 2 接上了單元 5 的延遲執行：從未呼叫 MoveNext() 時，連「開啟資源（進入 try）」都沒發生，自然不會執行那個 try 的 finally。C# 規格：Dispose 的行為

取得列舉器但從未呼叫 MoveNext() 就離開 using，主體的 finally 會？

04 / 預測三種結束路徑

下面的短版 Items(stopAt) 最多產出 1、2。三個 foreach 依序對應「正常結束」「產生端 yield break」「消費端 break」。先寫下全部輸出，再按核對。

static IEnumerable<int> Items(int stopAt)
{
    try
    {
        Console.WriteLine("Open");
        for (int n = 1; n <= 2; n++)
        {
            if (n == stopAt)
            {
                yield break;
            }
            yield return n;
        }
        Console.WriteLine("Done");
    }
    finally
    {
        Console.WriteLine("Clean");
    }
    Console.WriteLine("After");
}

foreach (int x in Items(0))
{
    Console.WriteLine("A" + x);
}

foreach (int x in Items(2))
{
    Console.WriteLine("B" + x);
}

foreach (int x in Items(0))
{
    Console.WriteLine("C" + x);
    break;
}

第一段完整走訪：A1、A2 暫停期間都不會先跑 Clean；第 3 次要求時離開 for 印出 Done，離開 try 印出 Clean，再執行外面的 After，之後 foreach 收尾呼叫 Dispose() 不會再跑第二次 Clean。第二段在第 2 次要求遇到 yield break，執行 Clean 後直接結束，沒有 Done 與 After。第三段拿到 C1 後由消費端 break，foreach 收尾呼叫 Dispose() 執行 Clean，同樣沒有 Done 與 After。這段程式於 2026-11-23 以 .NET 10 在暫存專案實測。

目標：不用重寫 try／finally，直接沿用 TerminationAndCleanup.cs 裡的 ReadNumbers(stopAt)，比較產生端與消費端同時設有結束條件時誰先觸發。

public static void RunExerciseAnswer()
{
    Console.WriteLine("練習 A：stopAt = 3，消費端在 4 才 break");
    ConsumeWithBreak(3, 4);

    Console.WriteLine("練習 B：stopAt = 3，消費端在 2 就 break");
    ConsumeWithBreak(3, 2);
}

private static void ConsumeWithBreak(int stopAt, int consumerBreakAt)
{
    foreach (int number in ReadNumbers(stopAt))
    {
        Console.WriteLine("[消費端] 取得 " + number);
        if (number == consumerBreakAt)
        {
            Console.WriteLine("[消費端] 達到消費端上限 " + consumerBreakAt + "，執行 break");
            break;
        }
    }
    Console.WriteLine("[消費端] foreach 結束");
}

合上教材，用自己的話說

回答兩題。你可以把解釋貼回聊天，我會依你的說法補充。

  1. 比較產生端的 yield break 與消費端 foreach 裡的 break：各自寫在哪裡、負責結束什麼？消費端 break 之後，迭代器裡還沒跑完的一般程式會繼續執行嗎？
  2. 消費端在 foreach 中途 break 時沒有手寫 Dispose()，為什麼產生端已進入的 finally 仍會執行？如果改用手動呼叫 GetEnumerator() 列舉，或是取得了列舉器卻從未呼叫 MoveNext()，這兩點會有什麼不同？
解釋題判準

能說出四點即可：第一，yield break 寫在迭代器方法（產生端）內，用來提早結束整個序列，讓當次 MoveNext() 回傳 False；消費端的 break 寫在 foreach 迴圈內，用來停止消費端自己的迴圈、不再索取下一個元素。第二，消費端 break 不會讓迭代器繼續執行剩餘的一般程式，只會處理已進入區塊的清理。第三，foreach 語意上帶有外圍 finally，離開迴圈時會自動呼叫列舉器的 Dispose()，進而觸發產生端目前已進入 try 對應的 finally；若是手動呼叫 GetEnumerator()，沒有 foreach 代勞，必須由使用者自己用 using（或手動呼叫 Dispose()）負責清理。第四，若取得列舉器後從未呼叫 MoveNext()，主體根本還沒開始、也還沒進入 try，此時 Dispose() 不會執行主體內的 finally。

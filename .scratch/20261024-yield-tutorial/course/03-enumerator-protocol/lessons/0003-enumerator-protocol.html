01 / 兩個角色

上一課說 IEnumerable<int> 約定「可以走訪」。真正走訪時，分成兩個角色：

角色型別負責
可列舉序列IEnumerable<int>用 GetEnumerator() 交出一個新的列舉器
列舉器IEnumerator<int>記住目前位置；MoveNext() 前進、Current 讀值、Dispose() 收尾

序列像一本書，列舉器像書籤：同一本書可以同時夾好幾張書籤，每張各自記得讀到哪。官方：IEnumerator<T> 備註

先猜猜看：剛呼叫 GetEnumerator() 時，列舉器在哪裡？

02 / MoveNext 決定能不能讀 Current

MoveNext() 往前移一格：移到一個元素上就回傳 True；已經越過最後一個元素就回傳 False，之後再呼叫也一直是 False。

序列有三個元素，第幾次 MoveNext() 會第一次回傳 False？

以 10, 20, 30 為例，每次 MoveNext() 後的狀態：

動作回傳位置Current
GetEnumerator()—第一個之前未定義
第 1 次 MoveNext()True1010
第 2 次True2020
第 3 次True3030
第 4 次False最後一個之後未定義
第 5 次以後False仍在結尾未定義

規則只有一句：最近一次 MoveNext() 回傳 True，才讀 Current。官方：MoveNext · 官方：Current

「未定義」是指規格不保證結果，不是「會得到 null」。2026-11-07 以 .NET 10 實測，在不合法的時點讀 Current：

列舉器來源實測結果
List<int>讀到 0
List<string>讀到 null
int[]擲出 InvalidOperationException

三種結果都只是特定實作的行為，程式不應依賴任何一種。

IEnumerator<int> enumerator = numbers.GetEnumerator();
int a = enumerator.Current;        // A

if (enumerator.MoveNext())
{
    int b = enumerator.Current;    // B
}
哪一行讀 Current 的時機合法？

03 / 用 using 收尾

IEnumerator<T> 也實作 IDisposable。有些列舉器背後連著檔案或資料庫，走完要釋放。using 區塊在離開時一定呼叫 Dispose()，中途發生例外也一樣。官方：using

using (IEnumerator<int> enumerator = numbers.GetEnumerator())
{
    while (enumerator.MoveNext())
    {
        int number = enumerator.Current;
        Console.WriteLine(number);
    }
}

這段就是 foreach (int number in numbers) 的概念對照：C# 規格把 foreach 定義為「取得列舉器 → while (MoveNext()) 讀 Current → 在 finally 中 Dispose」。C# 規格：foreach

適用範圍：本例的 numbers 宣告為 IEnumerable<int>。若宣告為 List<int>，編譯器會改用 List 自己的列舉器型別；陣列也另有處理。走訪規則相同，細節不在本課範圍。

List 的列舉器沒有資源要釋放，所以這一課看不出 Dispose 的效果；單元 6 會用 yield 方法親眼看到清理發生。

手動列舉為什麼要放進 using？

先讀程式，想好每一行輸出，再按核對。

IEnumerable<int> numbers = new List<int> { 10, 20, 30 };

using (IEnumerator<int> enumerator = numbers.GetEnumerator())
{
    Console.WriteLine(enumerator.MoveNext());
    Console.WriteLine(enumerator.Current);
    Console.WriteLine(enumerator.MoveNext());
    Console.WriteLine(enumerator.Current);
    Console.WriteLine(enumerator.MoveNext());
    Console.WriteLine(enumerator.Current);

Console 輸出 bool 時寫成 True／False。三個元素需要第四次 MoveNext() 才知道結束；這段程式在結束後沒有再讀 Current，所有讀取都合法。

05 / 自己改一次

目標：用手動列舉走訪另一組固定資料，並數出 MoveNext 呼叫幾次。

  1. 建立 IEnumerable<int> numbers = new List<int> { 2, 4, 6, 8 };。
  2. 用 using 與 while (enumerator.MoveNext()) 走訪，每行輸出「第 n 個：值」。
  3. 迴圈結束後，輸出元素個數與 MoveNext() 的呼叫次數。

先預測 MoveNext 會被呼叫幾次，再寫程式。可以寫在 EnumeratorProtocol.cs 新增的方法中。

修改題參考解
IEnumerable<int> numbers = new List<int> { 2, 4, 6, 8 };
int position = 0;

using (IEnumerator<int> enumerator = numbers.GetEnumerator())
{
    while (enumerator.MoveNext())
    {
        position++;
        Console.WriteLine("第 " + position + " 個：" + enumerator.Current);
    }
}

Console.WriteLine("共 " + position + " 個元素，MoveNext 呼叫 " + (position + 1) + " 次");

實測輸出：

第 1 個：2
第 2 個：4
第 3 個：6
第 4 個：8
共 4 個元素，MoveNext 呼叫 5 次

四次 True 各帶來一個元素，再一次 False 結束迴圈，共五次。專案另附獨立解答：dotnet run -- 03-answer。

合上教材，用自己的話說

下面有兩處讀取 Current 的時機不合法。指出是哪兩處、為什麼，再說明手動列舉為什麼要放進 using。你可以把解釋貼回聊天，我會依你的說法補充。

using (IEnumerator<int> enumerator = numbers.GetEnumerator())
{
    Console.WriteLine(enumerator.Current);      // A

    while (enumerator.MoveNext())
    {
        Console.WriteLine(enumerator.Current);  // B
    }

    Console.WriteLine(enumerator.Current);      // C
}
解釋題判準

能說出三點即可：A 在第一次 MoveNext() 之前，列舉器還在第一個元素之前；C 在 while 結束後，最近一次 MoveNext() 已回傳 False。A、C 的 Current 都未定義，可能讀到 0、null 或擲出例外，不能說一定是 null；B 在回傳 True 後讀取，是合法的。IEnumerator<T> 實作 IDisposable，using 保證離開區塊時呼叫 Dispose()，即使中途發生例外。

01 / 先讀懂角括號

原案例的方法長這樣：

private static IEnumerable<int> EnumerateRoundFacts(...)

角括號裡的型別告訴泛型型別「處理哪種資料」。官方：泛型

寫法讀法
List<int>元素型別是 int 的清單
IEnumerable<int>可以逐一取得 int 的序列

IEnumerable<T> 是介面：一份能力約定。實作它的類別必須提供約定的成員；使用它的程式只依賴約定，不必知道實際類別。List<T> 的宣告列出它實作 IEnumerable<T>，所以 List 可以交給這種型別的變數。官方：介面 · IEnumerable<T>

02 / 賦值不是複製

List<int> list = new List<int> { 10, 20, 30 };
IEnumerable<int> sequence = list;

List 是類別，變數保存的是物件參考。第二行讓 sequence 指向同一個 List 物件：沒有建立新集合，也不是拍下當下內容的快照。官方：參考型別

IEnumerable<int> sequence = list; 做了什麼？

03 / 宣告型別決定能寫什麼

物件仍然是 List，但編譯器依變數的宣告型別檢查成員。IEnumerable<int> 只約定「可以走訪」。先想想：

sequence 宣告為 IEnumerable<int>，哪一行可以直接編譯？

同一個物件，透過兩種宣告型別能直接寫的操作：

寫法listsequence
foreach 走訪可以可以
.Add(50)可以不能編譯
[0] 索引可以不能編譯
.Count 屬性可以不能編譯

方法名稱前的型別是回傳型別：

private static IEnumerable<int> GetNumbers(List<int> numbers)
{
    return numbers;
}

讀作「接收一個 List<int>，回傳可逐一取得 int 的序列」。內部回傳的是 List，呼叫端只看到 IEnumerable<int>。

呼叫 GetNumbers(list) 拿到的值，宣告型別是什麼？

04 / 先預測，再執行

先讀程式，想好每一行輸出，再按核對。

List<int> list = new List<int> { 10, 20, 30 };
IEnumerable<int> sequence = list;
list.Add(40);

foreach (int number in sequence)
{
    Console.WriteLine(number);
}

預測題解答與原因
10
20
30
40

賦值沒有複製資料。列舉 sequence 讀的是這份 List 在列舉時的內容，已包含 40。

05 / 自己改一次

目標：讓 sequence 列舉時也看到 4。

  1. 建立 List<int> list = new List<int> { 1, 2, 3 };，以 IEnumerable<int> sequence = GetNumbers(list); 取得序列。
  2. 先試寫 sequence.Add(4);，建置並閱讀錯誤訊息。
  3. 改成可以編譯的寫法，再以 foreach 列舉 sequence。

可以寫在 EnumerableContract.cs 的 Run() 結尾。觀察完錯誤後，刪除無法編譯的那一行。

修改題參考解
List<int> list = new List<int> { 1, 2, 3 };
IEnumerable<int> sequence = GetNumbers(list);

list.Add(4);

foreach (int number in sequence)
{
    Console.WriteLine(number);
}

sequence.Add(4) 會得到 CS1061：IEnumerable<int> 未包含 Add 的定義。改由 list 新增；它與 sequence 是同一個物件，所以列舉輸出 1、2、3、4。

專案另附獨立解答：dotnet run -- 02-answer。

解釋題判準

能說出三點即可：賦值只讓兩個變數參照同一個 List，沒有複製，也不是快照；編譯器依宣告型別決定能直接使用的成員，IEnumerable<int> 只約定可走訪；List<int> 實作了 IEnumerable<int>，所以能交給該型別。

# yield 主線教材 spec

Status: ready-for-agent
Category: enhancement

確認日期：2026-10-24（Asia/Taipei）

## Problem Statement

學生希望讀懂並運用原筆記中的回合事實 yield 範例，但既有筆記直接從業務片段切入，未建立 List、泛型、介面、可列舉序列與列舉器的概念關係。片段缺少完整型別、可觀察的執行時間線，以及提前停止、重複列舉和保存結果的取捨。

需要從基礎逐步銜接實際案例的教材，支持解釋行為、預測輸出、修改範例，最後自行撰寫類似方法並依需求選擇 yield 或 List。

## Solution

依已確認的學習地圖，重編一篇主線筆記並製作一個 Console 示範專案，按概念相依關係安排九個單元。從最小數字範例開始，最後回到完整的回合事實案例。

每單元以一個主要問題為中心，採「簡短說明 → 範例 → 預測輸出 → 執行觀察 → 修改練習」，題目後另設解答區。後續課程 Ticket 依單元切分，用於組織教材工作，不作個人學習進度紀錄。

## User Stories

1. As a 學生, I want 從最小整數範例開始, so that 我能先專注理解集合與列舉。
2. As a 學生, I want 觀察 List 的新增、索引與 foreach, so that 我能區分儲存與走訪的操作。
3. As a 學生, I want 看懂泛型 T 的基本讀法, so that 我能理解 List<int> 與 IEnumerable<int> 的型別意義。
4. As a 學生, I want 理解介面的能力約定, so that 我能理解集合透過不同宣告型別使用時的差異。
5. As a 學生, I want 理解 List<T> 與 IEnumerable<T> 的關係, so that 我不會把可列舉介面誤認為另一個新建集合。
6. As a 學生, I want 看懂回傳 IEnumerable<T> 的方法宣告, so that 我可以閱讀原案例的方法簽章。
7. As a 學生, I want 手動操作 GetEnumerator、MoveNext 與 Current, so that 我能說明 foreach 如何取得下一個值。
8. As a 學生, I want 知道何時可以讀取 Current, so that 我不會依賴列舉器尚未開始或已結束時的值。
9. As a 學生, I want 對照 return 與 yield return, so that 我能區分回傳結果與逐項產出的行為。
10. As a 學生, I want 觀察暫停後的執行位置與區域變數, so that 我能推演下一次取值的結果。
11. As a 學生, I want 觀察呼叫方法、取得列舉器與要求元素的時間線, so that 我能理解延遲執行。
12. As a 學生, I want 比較正常走到結尾與 yield break, so that 我能撰寫有明確結束條件的序列。
13. As a 學生, I want 比較 yield break 與 foreach 內的 break, so that 我能區分產生端結束與消費端停止。
14. As a 學生, I want 透過完整示範觀察 Dispose 與 finally, so that 我能理解提前停止時的基本清理行為。
15. As a 學生, I want 觀察同一序列被再次列舉, so that 我不會假設先前結果一定已被保存。
16. As a 學生, I want 比較兩次列舉之間改變輸入的結果, so that 我能理解重新計算與可變資料的影響。
17. As a 學生, I want 區分兩次列舉間改變資料與列舉期間修改集合, so that 我不會混淆兩種情境。
18. As a 學生, I want 對照 yield、List 與 ToList 的結果保存方式, so that 我能依保存與重複使用的需求選擇寫法。
19. As a 學生, I want 知道效能比較的前提, so that 我不會認定 yield 一定更快或不需要配置記憶體。
20. As a 學生, I want 執行具備完整最小型別的回合事實案例, so that 我不需取得外部遊戲專案才能理解情境。
21. As a 學生, I want 比較零個、一個與多個回合事實及其順序, so that 我能驗證條件組合。
22. As a 學生, I want 對照回合事實的 List 與 yield 版本, so that 我能根據同一需求解釋取捨。
23. As a 學生, I want 在解答前先預測與修改程式, so that 我能自行推理後再核對原因。
24. As a 學生, I want 清楚辨認主線與選讀內容, so that 我能先建立實務使用所需的概念。
25. As a 講師, I want 每張課程 Ticket 列出目標、先備知識、範圍、示範、練習與驗收條件, so that 我能按相依關係準備教材。
26. As a 知識庫讀者, I want 筆記、範例與索引彼此連結且保留案例及來源脈絡, so that 我日後能按知識主題查詢。

- 使用既有用語：學習地圖、教材 spec、課程 Ticket。
- 一篇主線筆記與一個 Console 示範專案，專案內依單元區分範例，不為每單元建立獨立專案。
- 主線順序與邊界如下：

| 單元 | 主要問題 | 必要內容 |
|---|---|---|
| 1 | List 如何保存與提供多個值？ | 最小整數範例、List<int>、新增、索引、foreach |
| 2 | 為什麼 List 可以交給 IEnumerable？ | 泛型讀法、介面能力約定、List<T> 與 IEnumerable<T> 關係、方法回傳型別讀法 |
| 3 | foreach 如何取得下一個值？ | GetEnumerator、IEnumerator<T>、MoveNext、Current、手動列舉與必要清理示範 |
| 4 | yield 如何分次提供元素？ | return 與 yield return、暫停與繼續、區域變數保留 |
| 5 | 迭代器方法何時真正執行？ | 呼叫、取得列舉器與逐次要求元素的時間線 |
| 6 | 序列如何結束或提前停止？ | 方法結尾、yield break、消費端 break、Dispose 與 finally 基本清理 |
| 7 | 為什麼再次列舉可能得到不同結果？ | 重複計算、副作用、可變輸入；區分列舉期間修改集合 |
| 8 | 何時選 yield，何時保存成 List？ | ToList、保存與重複使用、附帶前提的記憶體與執行成本比較 |
| 9 | 如何整理一個回合的多項事實？ | 完整最小型別、零／一／多個結果及順序、List 與 yield 版本對照 |

- 各單元只引入解答主要問題所需的新概念；介面與泛型不擴大為完整專題。
- 各單元提供簡短說明、可執行範例、預測輸出題與修改練習。題目少量且目的明確，解答在題目後獨立呈現並說明原因。
- 清理行為提供完整可執行示範，手動列舉亦正確處理生命週期。foreach 展開只作概念對照並交代適用範圍。
- 重編既有 yield 筆記，保留原案例、既有題目作答與來源脈絡，移除外部行號依賴；用最小必要型別避免遊戲系統依賴。
- 正式教材歸入集合與迭代的既有分類，更新知識庫索引配對筆記與範例，跨主題入口連至同份內容。
- 不改動其他既有範例的框架設定；新示範的目標框架在製作前依可用 SDK 與專案慣例確認。
- 後續按九個主要問題各建立一張課程 Ticket，列出目標、先備知識、講解範圍、示範、練習、驗收條件與相依 Ticket，不綁定課次時間。
- Ticket 狀態代表教材工作的狀態，不代表學生掌握程度。

## Testing Decisions

- **驗證入口**：以 Console 示範的輸入、輸出、執行事件順序與清理結果為主。這沿用學生已確認的解釋、預測與修改方式，不新增用來測試編譯器內部結構的介面。
- **好的驗證**：使用固定輸入與可重現輸出驗證外部行為，不依賴編譯器產生的型別名稱、內部狀態欄位或特定反編譯結果。
- **驗證對象**：九個單元的示範、題目、解答與最終案例，筆記敘述須與執行結果一致。
- **核心情境**：完整列舉、只取部分元素、產生端結束、消費端提前停止與清理、同序列列舉兩次、兩次列舉間改變輸入，以及保存成 List 後再次使用。
- **案例驗證**：固定回合資料涵蓋零個、一個與多個事實，核對順序；對相同固定輸入完整列舉，確認 List 與 yield 版本的值序列相同。
- **題目驗證**：解釋題提供關鍵判準，預測題提供實測輸出，修改題提供可執行參考解與預期行為。這是教材驗收，不儲存學生作答或能力紀錄。
- **既有做法**：沿用知識庫 Console 範例的建置、執行方式，及既有列舉器筆記中的 MoveNext／Current 手動示意；不假定已有 yield 自動化測試框架。
- **執行檢查**：新專案成功建置，各單元與修改題參考解實際執行並核對輸出。必要的回歸檢查仍使用相同外部行為入口，不建立映照編譯器實作的測試。
- **內容檢查**：正式撰寫時依官方文件查證技術敘述，標示適用版本與驗證日期，檢查教材、範例及知識庫索引連結。
